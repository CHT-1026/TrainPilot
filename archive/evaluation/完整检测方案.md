# Agent自主检索能力检测方案

状态：设计完成，尚未实现新执行器、尚未运行新测评。旧闭卷结果保留为历史，不能改名为检索测评成绩。本文件不授权自动增加其他候选或裁判模型。

## 1. 测量目标与边界

主目标：在同一可检索资料、同一权限和工具预算下，比较模型能否自主确定检索词、选择工具、追查线索、辨别版本、补齐证据，最终给出正确且可溯源的答案。

模型能看到用户问题、工具说明、实际工具返回的原文；不能看到标准答案、证据清单、判分规则、旧回答、评分报告、答案所在路径或其他模型的运行记录。原文包含业务事实是正常输入，不是泄题。

主测单位为一项用户任务；多轮任务整体算一项，不把每轮当独立样本。相似改写题按事实/模板家族标记，不能靠复制同一个事实凑样本量。

| 层次 | 实际执行方式 | 能解释的问题 |
| --- | --- | --- |
| R0 检索器诊断 | 固定规范查询调用后端检索，不调用生成模型 | 资料能否被索引、召回、排序、正确过滤 |
| R1 自主检索主测 | 候选模型通过真实工具自主检索并回答 | 查询规划、工具调用、补查、证据选择、回答和引用 |
| R2 给定证据诊断 | 对失败任务提供同一组充分原文，再回答 | 区分检索失败与阅读推理失败；需要额外模型调用，单列预算，不默认执行 |

R0不是模型排行榜，R2不是自主检索成绩。真实平台HTTP/流式路由在R1指定子集中测试，不另外把同一任务计入主分母。

R0的规范查询由评测侧预先编写，只用于检索器诊断，不能传给R1模型或用于按题号选择检索结果。R1只接收题干、正常会话历史和工具说明，不能接收私有事实标签或正确版本选择提示。允许工具执行用户明确给出的日期过滤；需要比较版本的任务须提供可比较的原始记录，不能由工具按金标准直接选好答案。

## 3. 资料和答案隔离

1. 固定136份业务原文及版本元数据，保留原PDF/DOCX/XLSX/CSV；建立带页码、段落、工作表/单元格、chunk_id和内容SHA的索引。扫描件/OCR如有实际需求，单列真实样本和实现状态，不能用可提取文本PDF冒充OCR测试。
2. 代码/配置题使用单独白名单快照，只放要测的源码和公开配置；不放.env、API Key、用户真实业务数据。
3. 创建独立模型工作区：不包含eval_bench、research、题库、金标准、评测代码、旧报告、旧预测或可反查它们的Git历史。当前LocalTools默认根目录为项目，必须改为评测工作区后才能开测。
4. 金标准与评分器放在另一进程/目录，工具服务只能访问公开快照；不能仅靠提示词禁止读取答案。MCP服务和命令工作目录也绑定同一快照，不提供可任意执行Python/shell的入口。
5. 每个任务记录角色、权限和可见资料集合。权限测试用合成受限数据；金标准永远不属于任何模型账号的可见资料。
6. 没有答案题先用评分侧全文核验确实没有支持证据；有答案但被权限隐藏、来源不可访问、资料本身冲突，分别标记。

## 4. 题目设计：16个核心检索维度

下列配额是新题库建设目标，不是已经有800道合格检索题。构建后先审题、去近重复、验证工具可达性，再冻结题单；不能为填满配额造重复题。

| 维度 | 要测什么 | 通过所需证据/行为 |
| --- | --- | --- |
| 1 精确定位 | 找某参数、条款、人员职责 | 找到正确实体、字段及具体出处 |
| 2 同义与别名 | 口语、缩写、产品旧称 | 自主改写，定位同一实体，避免错误合并 |
| 3 模糊需求定位 | 用户不知道文件名或章节 | 从需求找到合适来源，避免无方向反复检索 |
| 4 两跳检索 | A提供名字/型号，再到B查属性 | 两个必要事实都有实际工具证据 |
| 5 三跳以上 | 人员—部门—产品—制度链 | 追完整证据链，不把署名/分管当授权或行政边 |
| 6 汇总去重 | 多文件中的部门/客户/设备 | 声明集合范围，别名去重，不把未检出当不存在 |
| 7 数值与单位 | 检索财务/参数后计算 | 正确找数、对齐分母和单位，保留算式 |
| 8 时间推断 | 相对年份、期限、工作日 | 先找锚点与计时规则，再计算；不自行补假期 |
| 9 历史与生效版本 | 指定日期适用哪份制度 | 区分发布/更新/生效/废止，历史问题按历史版本 |
| 10 冲突判断 | 不同文件数值或说法不一致 | 比较范围/动作/时点，未解释矛盾保留，不机械选更新时间最新 |
| 11 多约束筛选 | 同时满足负载、臂展、速度等 | 找完整候选集，处理不适用值，不能漏候选后称唯一 |
| 12 表格和跨表检索 | 工作表、汇总行、明细行 | 正确定位单元格，区分汇总与明细、缺失与零值，报告冲突 |
| 13 跨格式取证 | MD/PDF/DOCX/XLSX/CSV联合查询 | 每种证据都经过真实读取，引用正确页/表/段 |
| 14 长文与干扰 | 相近产品、旧参数、无关段落 | 找正确对象与段落，检出不等于读完 |
| 15 多轮检索更新 | 用户改型号、日期或范围 | 按最新条件重查受影响部分，不沿用失效答案 |
| 16 无答案与证据不足 | 缺记录、模糊边界、超出集合 | 合理查证后说明缺口，既不乱猜，也不一开始就拒答 |

代码检索、目录定位、公开配置查询作为上述维度的source_type分层，必须有足够真实代码任务而不只是业务文档。每题同时标业务域、格式、难度、源类型、跳数和事实家族。

数据库SQL、第三方API、外部网页属于扩展来源套件：当前仅核实project_docs MCP配置，不能假定数据库/Web搜索工具已经提供给模型。接入后才冻结相关题；缺项标not_implemented/not_run，不能用描述性回答充当实际执行。数据库使用只读快照；网页主对比使用固定页面/响应快照，另列实时联网轮，不混合两者结果。

另配工具故障/权限/注入套件：HTTP403、超时、断连、空结果、分页、重复结果、截断、数据中的越权指令。正常任务和故障任务分别统计；不能把错误处理表现当普通检索难度。

这些是交叉标签，不在400/800之外自动加题：需要候选模型参与的权限、注入、故障任务预先纳入冻结题单，并与相应维度重叠统计；纯协议故障使用确定性测试。未接通的来源套件不能混入主题单后计为模型能力失败，须单列未实现缺口。若另加实时联网或其他模型任务，先单列新增题数和调用预算，本计划默认不启用。

## 6. 工具与预算

主工具建议为kb_search、kb_read、table_query以及现有list_files/read_file/search_code/query_project_config；这些新名称是待实现适配器，不表示现在已注册。工具描述和返回值必须如实注明覆盖格式、检索方式、分页/截断、source_id与版本，不携带金标准提示。

kb_search只返回原文候选，不调用另一个问答模型、不给计算结论；kb_read分页返回原文及稳定定位。表格工具提供表头与真实单元格，不根据评测答案替模型算好结果。词法检索与MCP检索走同一公开快照，完整问答pipeline仅放系统验收轨，避免把平台内置推理算成候选模型的能力。

初始工程预算：每项任务最多8轮模型交互、12次工具调用、每次搜索最多10项；检索结果短片段，全文分页补查。初拟累计输出预算8192 token/任务（含可计量的reasoning），总时限600秒，单工具超时30秒。上下文按本地16384上限设计，输入和输出共同计入；不能每轮重新给8192而不计累计消耗。具体输入/工具描述占用须在协议预检中核算，预算不够时如实记budget_exhausted，不静默压缩或换模型。以上是拟定预算，不是已经验证足够。

供应商未公开隐藏推理用量时，不能声称精确执行了包含隐藏推理的累计上限；仅按可观测usage及请求额度限额，明确缺失字段和预算可比性限制。先离线核查协议参数和工具返回体大小，再冻结真实小批的预算；不得根据某模型成绩单独放宽。

主测只读，不测试业务写库、删除、邮件发送。代码查询不开放任意命令。命令工具只在受控测试源码中开放事先注册的只读命令，不能读取宿主其他目录。必要权限校验在工具边界执行一次，失败明确返回；不为正常调用叠加无意义预检或多级错误包装。

## 7. 金标准与判分

每题私有记录：明确时间/用户/范围、是否可回答、必要原子事实、支持事实的证据组、允许的等价证据、可接受答案、单位/误差/字段类型、计算规则、冲突解释及拒答边界。字段类型、是否含路径起点、金额单位等必须在题干明示，解决旧11题的编码歧义。

同一结论允许多条等价证据路径，不强制唯一搜索词、固定调用次数或唯一文档顺序。必须检索的事实只能使用本题工具真实返回的材料，靠猜中数字但无证据不能拿“有证据任务成功”分。

可回答性分为answerable、needs_clarification、not_in_corpus、permission_denied、tool_unavailable。正常有答案题要求事实证据；缺关键条件题可先正确澄清，不能强迫无意义搜索；无记录题要求与检索范围相称的查证；权限/故障题要求识别真实边界，不能声称资料不存在。每类配有相近的可回答对照题，按各自rubric判定任务成功，不把合理澄清误判为拒答，也不把全部拒答当作检索通过。

| 指标 | 定义与统计方式 |
| --- | --- |
| 主指标：有证据任务成功率 | 正常可回答题须完整答案正确、必要事实均有本题实际返回的充分证据、引用支持结论、未越权；澄清/无答案/权限/故障题按预先定义的查证与边界rubric。分母为预先冻结全部正式任务，超时/工具失败保留，各类别另报分母 |
| 答案正确率 | 仅看答案是否匹配必要事实，单独报告，不能替代检索成功率 |
| 必要证据覆盖率 | 已取得的必要事实数/可取得必要事实数，按证据组和替代路径判断；区分资料缺失与工具未检出 |
| Recall@k、MRR、nDCG@k | R0固定查询的候选层指标；逐跳记录R1候选排名。nDCG须先有人标相关度，无标注不捏造该指标；chunk与doc层分别报 |
| 全链证据成功率 | 多跳所需证据组全部获取的任务比例，不能只找到第一跳算通过 |
| 引用准确率/覆盖率 | 引用能支持其关联主张；必要主张具有引用的比例；区分提到文件名与真正定位支持段落 |
| 版本/时间选择正确率 | 按题目动作日及有效/废止关系选对版本，历史问题不按当前最新覆盖 |
| 工具调用质量 | schema正确、参数意图正确、服务确实执行、结果被正确使用；MCP发现/调用/返回分阶段留证 |
| 拒答与可回答性 | 可回答任务误拒答率、无答案任务正确说明不足率、越权/故障识别率，分别统计，避免靠全部拒答获高分 |
| 效率与可靠性 | 成功任务的调用数、token、重复无效查询率及p50/p95耗时；同时报告全部任务失败/超时，未成功任务不从总分母消失 |

主分采用严格任务通过，原子事实部分分同时展示。把“找到了但算错”“答案正确但引用不支持”“只能完成部分子问”分开，不用一个含义不明的准确率掩盖问题。

精确数值/集合/时间/JSON使用确定性规则；开放文本按预先写好的事实rubric审阅。评分界面隐藏模型名与顺序，保留人工/辅助审阅者身份；如果只有同一AI审阅，只能称辅助判分，不能称独立双盲。四模型所有分歧题和边界题优先复核，再抽审一致通过与一致失败，避免仅审失败。

故障注入单独成套记录。真实基础设施故障在用户端成功率中计失败，诊断表明确根因未定，不直接归为模型推理差；不因成绩低选择性重试。修参考后对所有受影响模型使用旧原回答离线重判并保留前后版本；改题、换索引、换提示或预算则新建run，不能把旧作答算新条件。

题目族聚类报告，重复模板不当作独立证据；主比较用同题的胜/负/同成同败，给宏平均和实际题型分布。区间估计按题目家族重采样，样本量不足时只给描述性结果，不预设显著性或保证70%-80%/95%。要证明微调收益还须同架构base/微调模型和训练测试隔离；Q6/Q4只比较量化条件。

## 8. 轨迹与复查记录

每项任务保存：run/model/qid/case-family/source快照SHA、角色、题干与提示词、工具schema；每轮工具名/参数/调用ID、实际原始返回及SHA、候选排名、分页/截断、实际交给模型的证据与累计阅读量；最终回答原文、结构化来源、finish_reason、模型ID、usage、耗时、故障和预算状态。

保存可审计的工具行动和简短依据，不要求模型披露隐藏思维链；供应商未返回的token/时延字段留null，不能估作精确成本。API费用、生成调用数、工具次数、GPU/加载/等待时间分别报告。密钥/认证头不落盘。

推荐记录文件：blind/tasks.jsonl、private/gold.jsonl、public/source_manifest.json、traces/{model}.jsonl、answers/{model}.jsonl、scores/{model}.jsonl、reports/summary.json/md、manifest.json及seals。金标准目录不在工具可见根目录内，以上为拟建结构。

## 9. 执行阶段与停止条件

1. 审题和资料准备：审改原题，补证据组和可回答性；冻结公开资料与金标准，删除题意歧义和近重复。此时不开模型。
2. 只读工具接入：实现隔离快照、kb_search/kb_read/table_query，验证MCP stdio和Streamable HTTP及模型候选注入。检查没有其他LLM路由；实现状态逐项登记。
3. 协议/防泄漏预检：使用本地确定性测试验证答案目录不可读、路径权限、引用ID、分页、错误状态、轨迹完整、断点续跑、服务健康。只读黄金路径不增加冗余兜底。
4. 真实小批：四模型先执行冻结核心400中的40项，覆盖全部维度及真实工具调用。小批题号、执行入口、工具/模型参数和判分规则均在调用前固定。该40项计入最终400/800，不额外扩充Q6题数。输入、资料、参数与执行入口完全未变且记录完整的终态均沿用，失败同样保留，不能只保留成功；若须改设计，旧pilot单列，另建run并披露物理调用，不能暗中重跑充数。
5. 正式主测：先完成共同400，再完成Q4另外400和两云端剩余题。每题落盘、终态保存；仅从未执行任务续跑，不能丢超时记录。
6. HTTP/流式子集：在核心400中预先指定40项通过隔离测试服务的生产路由执行，四模型使用相同入口；核对工具事件、最终答案/引用及流式收尾。它是第4、5阶段内部预分配的执行入口，不在完成400后再跑一遍，也不与第4阶段小批混为两套新增题。候选必须可显式切换，否则先修接入，不走默认模型冒充候选。HTTP子集单独报告，直接工具执行子集也分别报告，不能将混合入口的总体差异直接解释为纯模型差异。
7. 评分与复议：规则判分、隐藏模型身份的语义审阅、同题分歧复核、故障归因。失败原因分解析/索引/召回/排序/上下文裁剪/规划/工具执行/推理/引用/基础设施，证据不足时标未确定。
8. 验收与恢复：核对所有任务号/范围/哈希/引用/隐藏金标准，封存报告与原轨迹；恢复本地临时设置。

发现答案泄漏、调用未授权模型、索引/工具条件不一致或轨迹缺失，立即停止该批并标invalid_run，修正后新建运行。分数不理想不是停止或换题条件。不能仅凭进程存在或状态文件就判执行正常，须核对实际工具/模型响应与落盘进度。

本阶段只交付方案和计划清单，不启动模型、不修改已封存结果、不启动外部服务。开发、正式执行和结果各自留证，不把方案写完称实现完成。

## 10. 实施文件与验收交付

拟新增app/evaluation/retrieval/{contracts,runner,tools,trace,grading}.py及scripts/retrieval_eval.py、config/retrieval_evaluation.json；文件按真实职责划分，不为转发参数新增空层。修改现有tools/agent.py和registry.py以传入本题模型与隔离工具配置；修改MCP服务支持指定快照和全文读取；RAG模块只暴露候选检索/读取，测试runtime注入四候选而不改全局.env。

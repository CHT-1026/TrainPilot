# 学习与实施路线

时间以实际启动日 D1 为起点，以下是投入较充分时的建议节奏，不是完成保证。用户尚未指定十一月投递日期；每个节点以验收成果为准。若到十一月前仍有未完成模块，应在 README 中如实标注。

| 节点 | 建议时间 | 验收成果 |
| --- | --- | --- |
| G0 环境与开源基线 | D1—D2 | 固定上游 SHA，完成 CPU 冒烟运行，短 GPU 试跑，估算费用 |
| G1 理解并训练 | D3—D7 | 最小训练循环，小规模预训练及 SFT，固定验证集和曲线 |
| G2 可测量实验 | D8—D12 | 阶段指标、Profiler 摘要、一组可复现性能对照 |
| G3 后端执行 | D13—D17 | 配置校验、串行 Worker、状态持久化、超时与结果归档 |
| G4 Agent 闭环 | D18—D23 | 工具选择、诊断假设、短实验验证、证据与停止条件 |
| G5 面试展示 | D24—D28 | 留出案例评测、失败分析、可复现演示、README 更新 |

## G0 环境与开源基线

- [ ] 熟悉 Python 环境、PyTorch CPU/CUDA 安装区别和张量形状。
- [ ] 核对 MiniMind 版本、许可证与数据许可，记录 commit SHA。
- [ ] 用小数据做 CPU 冒烟测试，再租 GPU 做限定时长试跑。
- [ ] 记录 GPU、驱动、框架版本、每步耗时、峰值显存与估算费用。

## G1 理解并训练

- [ ] 解释 token、标签右移、因果 Attention 和交叉熵。
- [ ] 自己写最小训练循环并对照参考实现检查。
- [ ] 完成小规模预训练和 SFT；检查 SFT 回答 token 的 loss mask。
- [ ] 固定数据划分和验证脚本，做一组学习率对比。

## G2 可测量实验

- [ ] 分开记录取数据、搬运、计算、保存与验证耗时。
- [ ] 定义有效 tokens/s 与显存口径，单独记录预热和编译耗时。
- [ ] 根据实测瓶颈选择改进，固定可比条件并重复测量。
- [ ] 检查优化后的验证损失，写出效果与代价。

## G3 后端执行

- [ ] 用 FastAPI 和 Pydantic 定义实验请求。
- [ ] 实现一个 GPU 串行 Worker 与 SQLite 状态存储。
- [ ] 校验配置、资源上限、路径与幂等键。
- [ ] 验证超时、取消、重启和断点恢复；禁止未测恢复结果当成已完成。

## G4 Agent 闭环

- [ ] 接入支持结构化工具调用的模型 API，不将凭证放入 Git。
- [ ] 实现日志读取、指标汇总、配置校验、短实验提交与结果比较工具。
- [ ] 用本地夹具开发 Agent，真实 GPU 仅用于必要验证。
- [ ] 完成至少一个端到端真实演示，保存脱敏调用轨迹。

## G5 面试展示

- [ ] 冻结开发案例与留出评测案例，区分合成夹具与真实实验。
- [ ] 对比静态规则、仅日志问答和带工具 Agent。
- [ ] 整理正确诊断、失败恢复、证据不足三个演示。
- [ ] 更新 README、报告、Word 文档和真实完成状态。
- [ ] 按真实结果选择合适的 Git 标签，再准备简历描述。

## 延误时如何缩减

保留单卡、小数据、CLI、单模型 API和少量诊断类型。先完成一次训练、一组性能对照和一个 Agent 实验闭环。多卡、CUDA 算子、大型前端、RAG 知识库和强化学习训练留到后续版本。

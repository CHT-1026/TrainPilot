# 澜图智能算法研发与模型上线规范(2026版)

## 一、模型选型

新项目模型选型须遵循"够用即可、成本可控、合规优先"原则:

1. 优先评估开源模型(Qwen、DeepSeek、Llama 系列),满足业务需求则不引入闭源 API。
2. 选型须有对比实验:至少对比 2 个候选模型,在相同评测集上报告准确率、延迟、显存占用、单次推理成本。
3. 涉及客户数据的场景必须私有化部署,禁止调用公网大模型 API。
4. 选型报告经算法负责人评审后归档。

## 二、数据集管理

1. 训练数据须来源合规,禁止使用未授权爬取或含个人隐私的数据。
2. 数据集须版本化管理(推荐用 DVC 或 git-lfs),每次更新记录来源、规模、清洗规则。
3. 标注数据须经过抽检,抽检不合格率超过 5% 须返工重标。
4. 敏感数据集(含个人信息)须脱敏后存储,访问权限最小化,操作留痕。

## 三、实验记录

每次训练实验须记录:
- 实验编号、时间、执行人
- 基座模型、版本
- 数据集版本、训练/验证集划分
- 超参数(学习率、batch size、epoch、LoRA rank/alpha 等)
- 训练指标(loss 曲线、验证集准确率)
- 产出物路径(权重、日志)

实验记录统一存于实验管理平台(推荐 MLflow 或自建),禁止仅存本地。可复现性是硬要求:他人凭记录应能复现你的结果。

## 四、模型评测

上线前模型须通过评测:
1. 自动评测:在业务评测集上达到约定阈值(准确率、F1、BLEU 等)。
2. 人工评测:至少 200 条抽样,双人标注,一致性 Kappa ≥ 0.7。
3. 安全评测:有害内容、偏见、越狱攻击的拦截率达标。
4. 性能评测:推理延迟 P99、吞吐 QPS、显存峰值满足上线要求。

评测报告不通过的模型禁止上线。

## 五、上线流程

1. 模型评测通过后提交上线申请,附评测报告与回滚方案。
2. 算法负责人 + 运维联合审批。
3. 灰度发布:先 5% 流量,观察 24 小时无异常再扩量至 50%,再 24 小时后全量。
4. 上线后监控核心指标(准确率、延迟、错误率),异常超阈值自动回滚。
5. 上线记录与模型版本归档,保留可追溯链路。

## 六、A/B 测试

效果优化须通过 A/B 测试验证:
1. 实验组与对照组流量均分,实验周期不少于 7 天或覆盖足够样本量。
2. 显著性检验:p < 0.05 且效应量满足业务要求方可判定有效。
3. 多重比较须做 Bonferroni 校正,避免假阳性。
4. 实验结论须记录在案,无效实验也要沉淀失败经验。
